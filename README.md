# Autonomous Programming Agent

This project implements an autonomous programming agent inspired by Manus AI and OpenManus. The agent uses the REACT (Reflect, Evaluate, Analyze, Correct, Test) technique integrated with Chain of Thought (CoT) to generate and execute Python or JavaScript code based on user commands. It features a FastAPI backend and a ReactJS frontend.

## Features

*   **REACT + CoT Agent:** Intelligent agent for autonomous code generation and problem-solving.
*   **Secure Sandbox:** Docker-based sandbox for safe code execution (Python currently supported).
*   **FastAPI Backend:** Robust Python backend providing RESTful APIs and WebSocket communication.
*   **ReactJS Frontend:** Interactive user interface for command input, real-time thought process display, code view, and results.
*   **Multi-User & Contextual Memory:** Supports multiple users with JWT authentication and maintains conversational context using Redis.
*   **Database Integration:** Uses MySQL (via SQLAlchemy and Alembic) for user data persistence.
*   **Scientific Data Interaction:** Includes a sample list of chemical elements for data manipulation tasks.
*   **Real-time Updates:** WebSocket integration for live updates of the agent's thinking process, now authenticated.
*   **Frontend Sandbox:** An iframe-based sandbox for rendering HTML/CSS/JS generated by the agent.

## Setup and Running

### Backend (FastAPI + Docker)

1.  **Navigate to Project Root:**
    Open your terminal in the project's root directory.

2.  **Database and Redis Setup:**
    *   Ensure your MySQL server and Redis server are running.
    *   Create a MySQL database for the application (e.g., `autonomous_agent_db`).
    *   Update `backend/config.py` with your actual `DATABASE_URL` and Redis connection details (`REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD`).
    *   Also, update `JWT_SECRET_KEY` in `backend/config.py` with a strong, unique secret.

3.  **LLM API Keys (Optional, for full functionality):**
    *   Copy your LLM API key(s) into `backend/config.py` (e.g., `GROQ_API_KEY`, `OPENAI_API_KEY`).
    *   The agent currently uses a placeholder LLM. To connect to a real LLM:
        *   Install the necessary Python client library (e.g., `pip install groq openai`). Add it to `backend/requirements.txt`.
        *   Update the `LLMClient` class in `backend/agent.py` to use the chosen LLM SDK and the API key from `config.py`.

4.  **Python Virtual Environment & Dependencies:**
    ```bash
    python -m venv .venv
    source .venv/bin/activate  # On Windows: .venv\Scripts\activate
    pip install -r backend/requirements.txt
    ```

5.  **Database Migrations (Alembic):**
    *   Apply database migrations to create the necessary tables (e.g., `users` table).
    *   Ensure `backend/alembic.ini` and `backend/alembic/env.py` are correctly configured to point to your database (via `config.py`).
    *   From the project root directory, run:
        ```bash
        cd backend 
        alembic upgrade head
        cd .. 
        ```
        *(Note: If you encounter issues with Alembic finding the `backend` package, you might need to adjust `PYTHONPATH` or run `alembic` from the `backend` directory after ensuring `env.py` correctly modifies `sys.path`.)*

6.  **Build the Docker Image:**
    ```bash
    docker build -t autonomous-agent-backend -f backend/Dockerfile backend
    ```
    *Note: The `-f backend/Dockerfile backend` syntax assumes Docker CLI is version 20.10+ that supports specifying build context separately. If using older versions, you might need to `cd backend` and run `docker build -t autonomous-agent-backend .` or adjust paths.*
    *A simpler command from project root if Dockerfile is efficient with context:*
    ```bash
    docker build -t autonomous-agent-backend ./backend
    ```


5.  **Run the Docker Container:**
    ```bash
    docker run -d -p 8000:8000 --name agent-app autonomous-agent-backend
    ```
    *   `-d` runs in detached mode.
    *   To view logs: `docker logs agent-app`
    *   To stop: `docker stop agent-app`
    *   To remove: `docker rm agent-app`

7.  **Alternative: Running Backend Directly with Uvicorn (for development):**
    Ensure you have activated the virtual environment, installed requirements, and applied database migrations.
    From the project root directory:
    ```bash
    uvicorn backend.main:app --reload --host 0.0.0.0 --port 8000
    ```

## API Endpoints

*   **`/auth` Endpoints:**
    *   `POST /auth/register`: Register a new user.
        *   Request Body: `{ "username": "user", "email": "user@example.com", "password": "password" }`
    *   `POST /auth/token`: Login to get an access token.
        *   Request Body: `FormData` with `username` and `password`.
    *   `GET /auth/users/me`: Get current authenticated user's details (requires token).
*   **`/generate` Endpoint:**
    *   `POST /generate`: Processes a user command with the agent. **Requires JWT Authentication.**
        *   Request Body: `{ "command": "your command here", "client_id": "your_unique_client_id" }`
        *   Authorization Header: `Bearer <YOUR_ACCESS_TOKEN>`
    *   Returns agent's final output. Intermediate updates via WebSocket.
*   **`/science-data` Endpoint:**
    *   `GET /science-data`: Returns the list of chemical elements (currently public).
*   **`/health` Endpoint:**
    *   `GET /health`: Health check for the backend (public).
*   **WebSocket Endpoint:**
    *   `WS /ws/agent-updates/{client_id}?token=<YOUR_ACCESS_TOKEN>`: WebSocket for real-time agent updates. **Requires JWT Authentication via token query parameter.**

## Multi-User Support & Contextual Memory

The application now supports multiple users through JWT-based authentication. Each user's interaction context with the agent (e.g., conversation history) is stored in Redis, keyed by `user_id` and `session_id` (currently `client_id` from the frontend). This allows the agent to maintain context across multiple commands within a session for a specific user.

When a user sends a command to the `/generate` endpoint:
1. The user must be authenticated (provide a JWT).
2. The backend retrieves the `user_id` from the JWT.
3. The agent loads the conversation history for that `user_id` and `session_id` from Redis.
4. The agent processes the command, using the loaded history to inform its actions (conceptual with current placeholder LLM).
5. After processing, the updated conversation history (including the current command and the agent's response) is saved back to Redis.

## Example Usage

1.  Ensure the backend and frontend servers are running.
2.  Open the frontend in your browser (e.g., `http://localhost:5173`).
3.  Enter a command in the input field, for example:
    `"Create a Python function that takes a list of chemical elements and returns the element with the highest atomic mass."`
4.  Click "Submit Command".
5.  Observe the agent's thought process, generated code, and execution results in real-time.

## Technology Stack

*   **Backend:** Python, FastAPI, Uvicorn, Docker
*   **Database:** MySQL (interacted via SQLAlchemy, migrations by Alembic)
*   **Cache/Context Store:** Redis (for agent contextual memory)
*   **Authentication:** JWT (python-jose, passlib)
*   **Frontend:** ReactJS, Vite, Material-UI, Axios
*   **Agent:** REACT + CoT methodology (LLM interaction is currently placeholder)
*   **Code Execution:**
    *   Backend Python: Dockerized sandbox.
    *   Frontend HTML/CSS/JS: Iframe sandbox in the browser.

## Configuration Variables

Key settings in `backend/config.py` that may need adjustment:

*   `DATABASE_URL`: Your MySQL database connection string.
*   `JWT_SECRET_KEY`: A strong, unique secret for JWT signing.
*   `ACCESS_TOKEN_EXPIRE_MINUTES`: Validity period for JWTs.
*   `REDIS_HOST`, `REDIS_PORT`, `REDIS_DB`, `REDIS_PASSWORD`: Redis server connection details.
*   `AGENT_CONTEXT_TTL_SECONDS`: How long agent context is stored in Redis.
*   `GROQ_API_KEY`, `OPENAI_API_KEY`: For LLM integration.
*   `DEFAULT_SANDBOX_TIMEOUT`, `DEFAULT_PYTHON_IMAGE`: For the Python execution sandbox.
